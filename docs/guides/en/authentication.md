# Authentication & Authorization (IAM)

## Overview

This guide explains the **Identity & Access Management (IAM)** implementation based on **JWT** used throughout the NestJS template. The security layer follows the **"Secure by Default"** principle – every route is protected unless explicitly marked as public.

## Core Components

| Component | Purpose |
|-----------|---------|
| `JwtStrategy` | Configures the `passport-jwt` strategy, extracts the token from the header and validates the signature. It dynamically extracts **Roles** and **Permissions** using paths defined in environment variables. |
| `JwtAuthGuard` | Global guard (`APP_GUARD`) that delegates authentication to `JwtStrategy`. Rejects requests without a valid token (401). |
| `RolesGuard` | Optional guard that checks if the authenticated user has the required **roles** defined via the `@Roles()` decorator. |
| `PermissionsGuard`| Optional guard that validates granular **permissions/scopes** defined via the `@Permissions()` decorator. |
| Decorators | `@Public()` – marks a route as public. `@Roles(...roles)` – declares required roles. `@Permissions(...perms)` – declares required permissions. `@CurrentUser()` – injects the decoded user payload. |
| `AuthModule` | Registers the strategy and guards, exposing them globally. |

## Configuration

1. **Environment Variables** – add these to your `.env`:
   ```bash
   JWT_SECRET=my-super-secret-jwt-key-for-local-dev-123
   # Optional: adjust paths based on your Identity Provider (e.g., Microsoft Entra ID, Google)
   AUTH_ROLES_CLAIM_PATH=roles
   AUTH_PERMISSIONS_CLAIM_PATH=permissions
   ```
2. **Auth Module** (`src/core/auth/auth.module.ts`):
   ```typescript
   @Module({
     providers: [JwtStrategy, JwtAuthGuard, RolesGuard],
   })
   export class AuthModule {}
   ```
   The guards are attached globally via `APP_GUARD` so you do not need to add them manually on each controller.
3. **Protecting Routes** – by default all routes require authentication.
   ```typescript
   @Get('health/integrations')
   getHealth() { … }                // Requires a valid JWT

   @Public()
   @Get('health')
   getHealth() { … }                // Public endpoint

   @Roles('ADMIN')
   @Get('admin')
   getAdminData() { … }             // Requires JWT + ADMIN role

   @Permissions('reports:view')
   @Get('reports')
   getReports() { … }               // Requires JWT + 'reports:view' permission

   @Roles('MANAGER')
   @Permissions('billing:write')
   @Patch('billing')
   updateBilling() { … }            // Requires JWT + MANAGER role AND 'billing:write' permission
   ```

## Generating a JWT for Development

A small helper script is provided at `scripts/generate-token.ts`. It is also available via the Makefile:
```bash
make auth-token
```
The script prints a ready-to-use token and the payload used for signing. Edit the `payload` constant in the script to simulate different users, roles, and permissions:
```typescript
const payload = {
  sub: 'user-123',
  email: 'test@example.com',
  roles: ['ADMIN'],
  permissions: ['health:read', 'integrations:write'],
};
```

## Using the Token in Requests

### cURL
```bash
TOKEN=$(npx ts-node scripts/generate-token.ts | grep -E '^ey' | head -n1)
curl -H "Authorization: Bearer $TOKEN" http://localhost:3000/v1/health/integrations
```

### Postman / Insomnia
1. Create a request.
2. In the **Authorization** tab select **Bearer Token**.
3. Paste the token generated by the script (do **not** include the word *Bearer* – the client adds it automatically).

### Swagger UI
The Swagger module is already configured with `@ApiBearerAuth()` for protected endpoints. Click the lock icon, paste the token (only the value), and click **Authorize**.

## Testing the Authentication Layer

### Unit Tests
- `src/core/auth/strategies/jwt.strategy.spec.ts` – validates payload handling and secret usage.
- `src/core/auth/guards/jwt-auth.guard.spec.ts` – ensures the guard returns 401 when the token is missing or invalid.
- `src/core/auth/guards/roles.guard.spec.ts` – covers role checks, including scenarios with empty role arrays.

### End-to-End (E2E) Test
Located at `test/health.e2e-spec.ts`:
```typescript
let jwtService: JwtService;

beforeAll(async () => {
  await helper.bootstrap();
  jwtService = helper.getApp().get<JwtService>(JwtService);
});

it('/v1/health/integrations (GET)', () => {
  const token = jwtService.sign({ sub: 'e2e-user', roles: [] });
  return request(helper.getApp().getHttpServer() as never)
    .get('/v1/health/integrations')
    .set('Authorization', `Bearer ${token}`)
    .expect(200);
});
```
The test uses the real `JwtService` from the Nest container to generate a valid token, guaranteeing the same secret and configuration used by the application.
